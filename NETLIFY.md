# Развёртывание через Netlify

## Сначала важная честность: сервер на Netlify не запустится

Netlify — хостинг **статических сайтов**. Он отлично раздаёт готовые
страницы, но **не умеет держать постоянно работающий сервер**:

* онлайн-чат работает через WebSocket — постоянное соединение,
  которое Netlify не поддерживает;
* база данных `db.json` и загруженные логотипы живут на диске —
  у Netlify нет постоянного диска;
* распределение чатов по операторам требует процесса, который
  работает круглосуточно.

Поэтому правильная схема такая:

```
┌────────────── NETLIFY (бесплатно) ──────────────┐
│  главный сайт   │  кабинеты   │  админ-панель   │
└────────┬────────┴──────┬──────┴────────┬────────┘
         │               │               │
         └───────────────┼───────────────┘
                         ▼
        ┌────────────────────────────────┐
        │   ВАШ СЕРВЕР (VPS) — server/   │
        │   API + чат + база + логотипы  │
        │   адрес: api.вашдомен.com      │
        └────────────────────────────────┘
```

Три сайта — на Netlify. Сервер — на вашем VPS (как поставить его —
файл `DEPLOY.md`, там же подключение домена и бесплатный HTTPS).

---

## Шаг 1. Поднять сервер (одно из двух)

**Вариант А — ваш VPS (рекомендую).** Следуйте `DEPLOY.md`: там Docker,
домен `api.вашдомен.com` и сертификат. Для Netlify-схемы достаточно
поднять только службу `server` и nginx для домена api.

**Вариант Б — облако типа Render.com.** Быстро и без своего VPS:
создаёте Web Service из папки `server`, команда запуска `npm start`.
⚠️ Но: на бесплатном тарифе диск НЕ сохраняется — база с перепиской
и сотрудниками обнулится при каждом перезапуске. Для рабочей
платформы нужен платный постоянный диск или свой VPS.

Запомните адрес сервера — он понадобится ниже
(например `https://api.olanhightech.com`).

---

## Шаг 2. Выложить три сайта на Netlify

Файлы `netlify.toml` уже лежат в каждой папке — Netlify сам всё поймёт.

Для **каждого** из трёх сайтов (site-client, portal-staff, admin-panel):

1. Зайдите на netlify.com → **Add new site → Import an existing project**
2. Подключите ваш Git-репозиторий с проектом
   (либо перетащите папку `dist` после локальной сборки — см. ниже)
3. В настройках импорта укажите **Base directory**:
   * `site-client` — для главного сайта
   * `portal-staff` — для кабинетов
   * `admin-panel` — для админ-панели
4. **Site settings → Environment variables → Add a variable:**

   | Ключ | Значение |
   |---|---|
   | `VITE_API_URL` | `https://api.вашдомен.com` |

   Это адрес вашего сервера из шага 1. Без этой переменной сайты
   будут искать сервер на localhost и чат не заработает.
5. **Deploy site**

Получится три сайта, например:
`olan-site.netlify.app`, `olan-portal.netlify.app`, `olan-admin.netlify.app`.

### Свой домен на Netlify

В каждом сайте: **Domain settings → Add custom domain** →
введите `olanhightech.com` (или `portal.…`, `admin.…`).
Netlify покажет, какую DNS-запись создать у регистратора домена, —
обычно CNAME на адрес сайта Netlify. HTTPS включится автоматически.

### Вариант без Git: вручную через папку dist

```bash
cd site-client
VITE_API_URL=https://api.вашдомен.com npm run build
```
Затем на Netlify: **Add new site → Deploy manually** → перетащите
папку `site-client/dist`. Повторите для двух других сайтов.
(Минус: при каждом изменении придётся собирать и перетаскивать заново.)

---

## Шаг 3. Разрешить сайтам обращаться к серверу

На сервере в файле `.env` (или в `ecosystem.config.cjs`, если без Docker)
перечислите адреса ваших сайтов через запятую:

```bash
ALLOWED_ORIGINS=https://olanhightech.com,https://portal.olanhightech.com,https://admin.olanhightech.com,https://olan-site.netlify.app,https://olan-portal.netlify.app,https://olan-admin.netlify.app
```

и перезапустите сервер: `docker compose up -d server`.

Без этого браузер будет блокировать запросы («Источник не разрешён»).

---

## Проверка

1. Откройте сайт на Netlify — тексты должны подтянуться с сервера
   (если видите встроенные русские тексты и чат «Соединение…» —
   проверьте `VITE_API_URL` и `ALLOWED_ORIGINS`)
2. Напишите в чат → сообщение должно прийти оператору в кабинете
3. Уведомления браузера заработают сразу — Netlify отдаёт HTTPS

## Частые проблемы

**Чат крутит «Соединение…».** Сервер недоступен или не в ALLOWED_ORIGINS.
Откройте F12 → Console на сайте — там будет видно, какой адрес блокируется.

**Сайт показывает старые тексты.** Забыли `VITE_API_URL` при сборке —
адрес вшивается именно в момент сборки, добавьте переменную и
пересоберите (Deploys → Trigger deploy).

**Всё работает по http, но не по https.** Сервер обязан быть на HTTPS
(`api.…` с сертификатом), иначе браузер режет смешанный контент.
