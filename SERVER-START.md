# Как запустить сервер

## Что случилось

Ошибка **«Не удалось получить данные»** на странице входа означает одно:
сайт на Netlify не смог связаться с сервером. Netlify раздаёт только
готовые страницы — **сервер там не работает**. Его нужно запустить
отдельно и указать сайтам его адрес.

Схема такая:

```
Netlify (три сайта)  ──запросы──▶  СЕРВЕР (нужно запустить)
                                   API + чат + база
```

Проверить, работает ли сервер, можно в любой момент — откройте
в браузере `https://адрес-сервера/api/health`. Если сервер жив,
он ответит `{"ok":true,...}`.

---

## Вариант 1. Render.com — быстро, без своего сервера

Подходит, чтобы прямо сейчас всё заработало. Render умеет WebSocket
(нужен для чата) и даёт бесплатный HTTPS.

### Шаги

1. Зайдите на [render.com](https://render.com) → **Get Started** →
   войдите **через GitHub**
2. **New +** → **Blueprint**
3. Выберите репозиторий `olan-platform` → **Connect**

   Render найдёт файл `render.yaml` в корне и всё настроит сам.

4. Он спросит два значения:

   | Переменная | Что вписать |
   |---|---|
   | `ADMIN_PASSWORD` | Пароль для входа в админ-панель (придумайте свой) |
   | `ALLOWED_ORIGINS` | Адреса ваших сайтов на Netlify, через запятую (см. ниже) |

   Для `ALLOWED_ORIGINS` впишите ваши реальные адреса, например:

   ```
   https://admin-panel-olan.netlify.app,https://olan-portal.netlify.app,https://olan-site.netlify.app
   ```

   Свои адреса посмотрите в панели Netlify — это имена всех трёх сайтов.

5. **Apply** → подождите 3–5 минут

Получите адрес вида `https://olan-server.onrender.com`.
Откройте `https://olan-server.onrender.com/api/health` — должно
появиться `{"ok":true,...}`. Значит сервер работает.

### Затем: указать адрес сервера сайтам

Для **каждого** из трёх сайтов на Netlify:

1. Netlify → выберите сайт → **Site configuration** →
   **Environment variables** → **Add a variable**

   | Key | Value |
   |---|---|
   | `VITE_API_URL` | `https://olan-server.onrender.com` |

2. **Deploys** → **Trigger deploy** → **Deploy site**

   Это обязательно: адрес сервера вшивается в сайт в момент сборки,
   поэтому после добавления переменной нужен новый деплой.

Через пару минут откройте админ-панель — вход заработает.

### ⚠️ Ограничения бесплатного тарифа Render

Скажу прямо, чтобы не было неожиданностей:

* **Сервер засыпает** после 15 минут без обращений. Первый запрос
  после сна идёт около 30 секунд — страница будет «думать».
  Для чата это неудобно: оператор может пропустить обращение.
* **База не сохраняется.** При каждом перезапуске файл с сотрудниками,
  перепиской и заявками обнуляется — придётся заново создавать
  менеджеров и операторов.

Для рабочей платформы нужно одно из двух:

* включить платный диск: в `render.yaml` раскомментируйте блок `disk`
  и смените `plan: free` на `plan: starter` (около $7/мес + $0.25/ГБ);
* либо разместить сервер на своём VPS — вариант 2 ниже, он и надёжнее,
  и дешевле в долгую.

## Вариант 2. Свой сервер (VPS) — правильный для рабочей версии

Здесь ничего не засыпает и база не теряется. Подробно — в `DEPLOY.md`,
кратко для случая «сайты на Netlify, сервер у меня»:

```bash
# 1. Подключиться к серверу
ssh root@ВАШ_IP

# 2. Установить Docker
curl -fsSL https://get.docker.com | sh

# 3. Скачать проект прямо с GitHub
apt install -y git
git clone https://github.com/ваш-логин/olan-platform.git
cd olan-platform

# 4. Заполнить настройки
cp .env.example .env
nano .env
```

В `.env` для этой схемы важны такие строки:

```bash
API_DOMAIN=api.вашдомен.com          # поддомен для сервера
DOMAIN=вашдомен.com
CERTBOT_EMAIL=ваша@почта.com

ADMIN_EMAIL=admin@olanhightech.com
ADMIN_PASSWORD=ВашСложныйПароль      # ⚠️ смените!
JWT_SECRET=                          # вставьте: openssl rand -hex 32

# адреса сайтов на Netlify — через запятую, без пробелов
ALLOWED_ORIGINS=https://admin-panel-olan.netlify.app,https://olan-portal.netlify.app,https://olan-site.netlify.app
```

Дальше:

```bash
# 5. Запустить только сервер и nginx (сайты живут на Netlify)
docker compose up -d --build server nginx

# 6. Выпустить бесплатный сертификат HTTPS
./deploy/ssl-setup.sh
```

В DNS домена создайте запись типа **A**: `api` → IP вашего сервера.

Проверка: `https://api.вашдомен.com/api/health` должен ответить
`{"ok":true,...}`.

Затем так же, как в варианте 1, укажите этот адрес в `VITE_API_URL`
у всех трёх сайтов на Netlify и запустите Trigger deploy.

## Вариант 3. Только для проверки: сервер у себя на компьютере

Так можно быстро убедиться, что всё работает, но **сайты на Netlify
к нему подключиться не смогут** — браузер не пускает защищённую
страницу (https) к незащищённому адресу на вашем компьютере.

Поэтому проверяйте локально целиком:

```bash
cd server
npm start
```

и открывайте `http://localhost:5175` (админка запускается отдельно
командой `npm run dev` в папке `admin-panel`).

---

## Порядок действий, если всё с нуля

1. Запустить сервер (вариант 1 или 2) → получить его адрес
2. Проверить `адрес/api/health` → должно быть `{"ok":true}`
3. Прописать этот адрес в `VITE_API_URL` у трёх сайтов на Netlify
4. На каждом сайте: Trigger deploy
5. В `ALLOWED_ORIGINS` на сервере перечислить адреса сайтов
6. Войти в админ-панель, создать менеджеров и операторов

---

## Диагностика

| Что видите | Что это значит | Что делать |
|---|---|---|
| «Не удалось получить данные» | Сервер не запущен или адрес неверный | Проверьте `адрес/api/health` |
| «Ошибка запроса к серверу» | Сервер отвечает, но запрос отклонён | Проверьте `ALLOWED_ORIGINS` |
| «Неверная почта или пароль» | Сервер работает! Просто пароль другой | Смотрите `ADMIN_PASSWORD` в настройках сервера |
| Долго грузится первый раз | Сервер на Render «просыпается» | Подождите 30 секунд |

Полезно смотреть подробности: на странице сайта нажмите **F12** →
вкладка **Console**. Там видно, к какому адресу шёл запрос и почему
не получилось.
